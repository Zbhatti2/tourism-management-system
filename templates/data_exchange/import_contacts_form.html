Import Contacts from CSV

Header row required, any case. Recognized columns (a name is the only requirement — either Full Name, or First Name/Last Name separately, e.g. a standard Outlook/Exchange contacts export):

  • Title, First Name, Last Name, Suffix — a Title/Suffix that doesn't exist yet is created automatically in Table Maintenance when committed.
  • Organization — optional; a company name that doesn't already exist in the Organizations table is created there automatically (bare — just a name) and linked to the contact.
  • Job Title, Categories, Notes — optional (a Category that doesn't exist yet is also created automatically; only the first of several ";"-separated categories becomes the contact's Category, the full list is kept in Notes).
  • Street, City, State, Business Postal Code, Country — optional; become one Business-tagged address, matching City/Province/Country against the geography already on file where possible.
  • Business Phone, Home Phone, Home Phone 2, Mobile Phone, Business Fax, E-mail Address, E-mail 3 Address — optional; each becomes its own phone/email entry. Several values crammed into one cell with ";" between them are split into separate entries.

A row is only treated as a duplicate of an existing contact when the name AND a phone number or email address both match — a shared name alone isn't enough (real files sometimes have two different people with the same name). A contact with no phone or email at all can't be matched this way, so re-running the import for that one row will add it again rather than silently skipping it.

Most common encodings are read automatically — UTF-8, and Windows-1252 (Excel/Outlook's usual "CSV" export) — so there's no need to re-save the file first.
