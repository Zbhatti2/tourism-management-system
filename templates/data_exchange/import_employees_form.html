Import Employees from CSV

Header row required, any case. Recognized columns (a name is the only requirement — either Full Name, or First Name/Last Name separately, e.g. a standard Outlook/Exchange contacts export):

  • Title, First Name, Middle Name, Last Name, Suffix — Middle Name is folded into Full Name; Title/Suffix have no field of their own on Employees, so they're kept as labeled lines in Notes instead.
  • Company — optional; kept as a labeled line in Notes (Employees belong to your tenant directly, so there's no separate company link to make).
  • Department, Job Title — optional; a value that doesn't exist yet is created automatically in Table Maintenance when committed.
  • Gender — optional; kept as a labeled line in Notes (no dedicated field on Employees).
  • Address/Street, City, State, Postal Code, Country (or Country/Region) — optional; become the employee's one Address, matching City/Province/Country against the geography already on file where possible.
  • Fax, Phonea/Phone1 (both recognized as a plain "Phone"/office number), Phone2, Home Phone, Mobile Phone — optional; each becomes its own phone entry (Employees only have Fax/Home/Mobile/Office phone types, so Phonea/Phone1 and Phone2 both become "Office" numbers, the same way a second Home Phone column would). Several values crammed into one cell with ";" between them are split into separate entries.
  • E-mail Address, E-mail 2 — optional; each becomes its own email entry (an "E-mail 2 Display Name" column, by contrast, is recognized as Outlook metadata with no address in it, and is skipped).

A row is only treated as a duplicate of an existing employee when the name AND a phone number or email address both match — a shared name alone isn't enough (this file, for instance, has three different employees who share the surname Bhatti). An employee with no phone or email at all can't be matched this way, so re-running the import for that one row will add it again rather than silently skipping it.

Most common encodings are read automatically — UTF-8, and Windows-1252 (Excel/Outlook's usual "CSV" export) — so there's no need to re-save the file first.
